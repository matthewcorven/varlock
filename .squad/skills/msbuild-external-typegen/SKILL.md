# SKILL: Deterministic External Typegen in MSBuild

**Version:** 1.0  
**Author:** Geordi (MSBuild & Typegen Lead)  
**Context:** Varlock `.NET` support, external generator integration  
**Last Updated:** 2026-03-15

## Purpose

When a `.NET` project needs to consume code generated by an external tool during build, wire it so the output is deterministic, incremental, and kept out of the tracked source tree.

## Pattern

1. **Write generated code to `obj/`**  
   Use a stable intermediate path like `obj/Varlock/AppConfig.g.cs`, not a repo-tracked `Generated/` folder.

2. **Keep generation and compile inclusion separate**  
   - One target runs the external generator with `Inputs` / `Outputs`
   - A second target runs before `CoreCompile` and adds the generated file to `@(Compile)`

3. **Make the generated path explicit in both places**  
   The schema/decorator path and the MSBuild property (for example `VarlockGeneratedFile`) must agree. If they drift, fail the build loudly.

4. **Treat stale tracked generated files as hazards**  
   Remove or exclude old `Generated/**/*.g.cs` items so a previous checked-in artifact cannot compile beside the new `obj/` output.

5. **Prove incrementality with a second unchanged build**  
   In proof code, capture the generated file timestamp after the first build, run `dotnet build` again, and assert the file was not rewritten.

6. **Check design-time compile inclusion after generation**  
   After a successful real build creates the `obj/` artifact, run a design-time build such as `dotnet build -p:DesignTimeBuild=true` to confirm the generated file can be consumed without forcing generation during design-time evaluation. Treat that as IDE hygiene proof only — not as `dotnet watch` or full IDE parity proof.

## When to Use

- Bridging an existing CLI generator into MSBuild
- Migrating from checked-in generated files to intermediate outputs
- Adding the first build-integrated type-generation slice before analyzers or source generators

## Varlock Example

- Schema decorator: `@generateTypes(lang=cs, path=obj/Varlock/AppConfig.g.cs, ...)`
- MSBuild property: `<VarlockGeneratedFile>$(BaseIntermediateOutputPath)Varlock/AppConfig.g.cs</VarlockGeneratedFile>`
- Proof: `scripts/test-dotnet-proof.ts` removes `obj/Varlock`, builds once, asserts file exists, then builds again and asserts the timestamp is unchanged
