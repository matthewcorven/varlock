While plain string keys work fine with `IConfiguration`, Varlock can generate strongly-typed C# classes from your schema. This gives you full IntelliSense support, compile-time type checking, and cleaner code.

## Generate types from your schema

### Add the generation directive

In your `.env.schema`, use the `@generateTypes` directive:

```javascript
/**
 * @env-spec
 * @defaultSensitive false
 * @generateTypes(lang=cs, typeName=VarlockConfig, path=Generated/VarlockConfig.g.cs)
 */

APP_NAME = @string @default("my-app")
APP_PORT = @integer @default(5000)
DATABASE_URL = @string @required
API_KEY = @string @sensitive
```

Parameters:
- **lang=cs** — Generate C# (required for .NET)
- **typeName=VarlockConfig** — Name of the generated class (use PascalCase)
- **path=Generated/VarlockConfig.g.cs** — Output path relative to your project root

### Generate the code

Run the schema validation (which happens at build time and startup):

```bash
varlock load --format json-full
```

The first time you add `@generateTypes`, a rebuild will generate the file:

```bash
dotnet clean
dotnet build
```

Your generated file appears at the path you specified:

```csharp
// Generated/VarlockConfig.g.cs
public sealed class VarlockConfig
{
  public string AppName { get; }
  public int AppPort { get; }
  public string DatabaseUrl { get; }
  public string ApiKey { get; }
}
```

## Use generated types with IOptions<T>

### Basic binding with IConfiguration

The simplest way to use the generated type is to bind it from `IConfiguration`:

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Configuration.AddVarlock();
builder.Services.Configure<VarlockConfig>(builder.Configuration);

var app = builder.Build();

// Later, inject it
public class MyService
{
  private readonly IOptionsSnapshot<VarlockConfig> _options;

  public MyService(IOptionsSnapshot<VarlockConfig> options)
  {
    _options = options;
  }

  public void UseConfig()
  {
    string appName = _options.Value.AppName;  // Fully typed!
    int port = _options.Value.AppPort;
  }
}
```

### Create a custom options class

If you want to customize field names or add helper methods, create your own class instead:

```csharp
using Microsoft.Extensions.Configuration;
using Varlock.DotNet;

public sealed class AppConfig
{
  public string AppName { get; set; } = "";
  public int AppPort { get; set; }
  public string DatabaseUrl { get; set; } = "";
  public string ApiKey { get; set; } = "";

  /// <summary>
  /// Create an instance from IConfiguration.
  /// </summary>
  public static AppConfig FromConfiguration(IConfiguration config)
  {
    return new AppConfig
    {
      AppName = config["APP_NAME"] ?? "",
      AppPort = int.Parse(config["APP_PORT"] ?? "5000"),
      DatabaseUrl = config["DATABASE_URL"] ?? "",
      ApiKey = config["API_KEY"] ?? "",
    };
  }

  /// <summary>
  /// Helper to safely get the API key (which is marked @sensitive).
  /// </summary>
  public bool TryGetApiKey(out string apiKey)
  {
    apiKey = ApiKey ?? "";
    return !string.IsNullOrEmpty(apiKey);
  }
}
```

Then configure it:

```csharp
builder.Configuration.AddVarlock();
builder.Services.Configure<AppConfig>(config =>
{
  var appConfig = AppConfig.FromConfiguration(config);
  // Customize if needed
});
```

## Validation

### ValidateOnStart()

For critical configuration, validate it immediately on startup instead of waiting for first use:

```csharp
builder.Configuration.AddVarlock();

builder.Services
  .Configure<VarlockConfig>(builder.Configuration)
  .ValidateDataAnnotations()  // Validates decorated properties
  .ValidateOnStart();         // Fail fast if validation fails
```

Use data annotations to add extra validation:

```csharp
using System.ComponentModel.DataAnnotations;

public sealed class VarlockConfig
{
  [Required]
  public string AppName { get; set; } = "";

  [Range(1, 65535)]
  public int AppPort { get; set; }

  [Required, Url]
  public string DatabaseUrl { get; set; } = "";
}
```

### Schema-level validation

Varlock's schema validation is always applied, regardless of `ValidateOnStart()`:

```javascript
/**
 * @env-spec
 */

APP_PORT = @integer @min(1) @max(65535)
DATABASE_URL = @string @pattern(^https?://)
API_KEY = @string @required
```

Schema validation runs at startup (before `ValidateOnStart()`) and on every reload.

## Working with scopes

### IOptionsSnapshot<T>

Use `IOptionsSnapshot<T>` for request-scoped or short-lived configuration:

```csharp
public class MyController : ControllerBase
{
  private readonly IOptionsSnapshot<VarlockConfig> _options;

  public MyController(IOptionsSnapshot<VarlockConfig> options)
  {
    _options = options;
  }

  [HttpGet]
  public IActionResult Get()
  {
    // Gets fresh config for this request scope
    var config = _options.Value;
    return Ok(new { appName = config.AppName });
  }
}
```

When configuration reloads, the next request gets the new values automatically.

### IOptionsMonitor<T>

Use `IOptionsMonitor<T>` for long-lived services that need to track configuration changes:

```csharp
public class MyBackgroundService : BackgroundService
{
  private readonly IOptionsMonitor<VarlockConfig> _options;

  public MyBackgroundService(IOptionsMonitor<VarlockConfig> options)
  {
    _options = options;
  }

  protected override async Task ExecuteAsync(CancellationToken ct)
  {
    // Subscribe to changes
    using var changeToken = _options.OnChange(newConfig =>
    {
      Console.WriteLine($"Config updated: {newConfig.AppName}");
    });

    while (!ct.IsCancellationRequested)
    {
      // Always use CurrentValue to read the latest
      var appName = _options.CurrentValue.AppName;
      
      // Do work...
      await Task.Delay(TimeSpan.FromSeconds(1), ct);
    }
  }
}
```

When configuration reloads successfully, `OnChange` is called with the new values. Failed reloads don't fire change notifications—the service continues with the last-known-good config.

## Serilog redaction

When you have sensitive values (marked with `@sensitive` in your schema), Varlock can automatically redact them in Serilog logs:

First, install the Serilog integration:

```bash
dotnet add package Varlock.Serilog
```

Then configure it:

```csharp
using Varlock.DotNet;
using Varlock.Serilog;

var runtime = new VarlockCliRuntime();
var graph = runtime.Load(new VarlockLoadOptions
{
  WorkingDirectory = builder.Environment.ContentRootPath,
});

var logger = new LoggerConfiguration()
  .Destructure.WithVarlockRedaction(graph)  // Redact @sensitive keys
  .Enrich.WithVarlockMetadata(graph)        // Add Varlock metadata
  .WriteTo.Console()
  .CreateLogger();

logger.Information("Connecting to {DatabaseUrl}", graph["DATABASE_URL"]);
// Output: "Connecting to [REDACTED]"
```

The `WithVarlockRedaction()` destructuring policy:
- Takes a snapshot of your schema's sensitive keys at configuration time
- Applies exact, case-sensitive redaction to any matching keys
- Redacts values inside destructured objects and dictionaries

The `WithVarlockMetadata()` enricher adds a `VarlockRedactLogs` property to all log entries for filtering and debugging.

### Manual redaction

For non-Serilog scenarios or manual redaction:

```csharp
var graph = new VarlockCliRuntime().Load(...);
var sensitiveValue = graph["API_KEY"];

// Redact manually
var redacted = VarlockRedactionHelper.Redact("API_KEY", graph) 
  ?? "[REDACTED]";

Console.WriteLine($"Using: {redacted}");
```

## Generated type naming

Varlock generates C# property names from environment variable keys by converting them to PascalCase:

| Environment key | Generated property |
| --- | --- |
| `APP_NAME` | `AppName` |
| `DATABASE_URL` | `DatabaseUrl` |
| `API_KEY` | `ApiKey` |
| `MY_SUPER_SECRET_KEY` | `MySuperSecretKey` |

The original key is always available through `IConfiguration[key]` with the exact casing.

## Public-only generation (Blazor WebAssembly)

If you're building a Blazor WebAssembly app, you can generate only public configuration (no sensitive keys) so it's safe to ship to the browser:

```javascript
/**
 * @env-spec
 * @generateTypes(
 *   lang=cs,
 *   typeName=VarlockPublicConfig,
 *   path=Generated/VarlockPublicConfig.g.cs,
 *   publicOnly=true
 * )
 */

APP_NAME = @string @default("my-app")
API_ENDPOINT = @string @default("https://api.example.com")
API_KEY = @string @sensitive  // Excluded from public generation
```

The generated `VarlockPublicConfig` contains only `AppName` and `ApiEndpoint`. The `API_KEY` is completely absent from the generated file and cannot be accessed.

This is build-time filtering, not runtime protection—the generated file simply doesn't contain sensitive metadata.

## Building with generated types

Generated types are created during the normal .NET build process. No extra steps needed:

```bash
dotnet build
```

The generated file is placed in the path you specified in `@generateTypes(path=...)`. 

If you use a path in the `obj/` directory (recommended for generated files), it's automatically excluded from source control and cleaned on `dotnet clean`.

## Troubleshooting

### "Property not found" error

If you get a binding error like "Property 'AppName' not found on type 'VarlockConfig'", make sure:

1. You added `@generateTypes` to your schema
2. You ran `dotnet build` to generate the file
3. The generated file exists at the path you specified
4. The property name matches the PascalCase conversion of your environment key

### Generated file not updating

After changing your schema:

```bash
dotnet clean
dotnet build
```

The build process regenerates the file automatically.

### Type mismatch in IOptions binding

If binding fails with a type error, check that your schema types match your options class properties. Varlock will coerce `@integer` and `@boolean` values to the correct .NET types during generation.
